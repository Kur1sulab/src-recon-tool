# 自研工具审计报告 · src-recon-tool

- 审计日期：2026-09-24
- 审计对象：`src/modules/` 全部模块（重点：`api_unauth`、`paths`）
- 审计方式：静态代码审查 + **可控靶站动态实测**（`tests/mock_server.py` + `tests/audit_probe.py`）
- 审计立场：以"这个工具会不会骗我"为前提 —— 对自研工具做对抗性验证，而不是自证清白

---

## 一、审计方法

不采信"看起来对"，用四类典型站点行为作对照，跑真流量看判定结果：

| 场景 | 模拟的线上行为 |
|---|---|
| `soft404` | SPA / 自定义错误页：**任意路径都返回 200 + 同一份 HTML 外壳** |
| `api404` | API 网关 catch-all：任意路径返回 200 + 泛化 JSON（含 id/username 等常见键） |
| `waf` | 全局 403（WAF 或权限网关拦截一切） |
| `loginredirect` | 任意路径 302 → 登录页（200 HTML） |
| `empty` | 标准 404（对照组） |
| `real` | 真实暴露：swagger / actuator / heapdump / `.env` / robots 都是真的 |

审计脚本：`python tests/audit_probe.py`（一键起靶站并输出各场景命中数）。

## 二、发现与修复

### F1（严重）探测没有"软 404 基线" —— 假阳性机器

- **现象**：`paths` 模块只按状态码判定。遇到 SPA / 自定义错误页时**任意路径都返回 200**，
  实测该场景下 19 条字典**全部**被报成"存活"；全局 403 站点同样报 19 条；302 统一的跳转站也报 19 条。
- **影响**：报告里会出现一堆"存在但无危害"的假发现 —— 与 EDUSRC 驳回理由（"无明显敏感信息/危害不足"）高度同源。
- **修复**：新增 `netutil.baseline()`：先用两个随机不存在路径取站点基线，识别
  `soft404 / uniform403 / redirect`；凡响应形态（状态码 + 内容指纹/长度+类型）与基线一致者一律剔除。
  实测修复后三类场景均为 **0 命中**。

### F2（严重）命中不做存活复验

- **现象**：两个模块都是"单发请求 → 直接报命中"，无法区分稳定暴露与瞬时响应（WAF 抖动、后端偶发 200）。
- **影响**：报告里可能出现"提交前已知失效"的漏洞。
- **修复**：新增 `netutil.verify_live()`：命中后**连续 2 次**复验，形态一致且特征仍在才记 `live=True`；
  `paths` 的存量条目同样带 `verified` 字段。输出中明确区分"存活"与"复验未通过"。

### F3（中）判定条件过于宽松

- **现象 1**：`heapdump` 原本"无特征 + 响应较大/二进制"即判定命中，任何大二进制软 404 都会误报。
  → **修复**：改为必须命中 `JAVA PROFILE` 魔数（真 heapdump 头部即此特征）。
- **现象 2**：`/api/v1/users` 等端点只要出现 `"id"` / `"username"` 任一个键即命中。
  → **修复**：多特征端点要求命中 **≥2 个**特征，避免泛化 JSON 误报。
- **现象 3**：`/actuator` 仅认 `"_links"`，与通用 JSON 链接字段易混淆。
  → **修复**：要求 `"_links"` + `"href"` 双特征。

### F4（低）跟踪重定向却不记录

- **修复**：结果中记录 `final_url` 与 `redirected` 标记，便于人工识别"被统一跳转走"的伪命中。

## 三、修复前后对照（实测）

| 场景 | api 修复前 | api 修复后 | paths 修复前 | paths 修复后 |
|---|---|---|---|---|
| soft404（SPA） | 0 | 0 | **19 误报** | **0** |
| api404（JSON 软 404） | **4 误报** | **0** | **19 误报** | **0** |
| waf（全局 403） | 0 | 0 | **19 误报** | **0** |
| loginredirect（302） | 0 | 0 | **19 误报** | **0** |
| empty（标准 404） | 0 | 0 | 0 | 0 |
| real（真实暴露） | 5 真命中 | **5 真命中 + 全部存活复验通过** | 5 真命中 | **5 真命中（verified）** |

结论：**假阳性归零，真阳性零损失**。

## 六、第二轮审计（同日，针对新增功能）

新增两项能力后立刻复审它们自己：

### 6.1 新增能力

| 能力 | 说明 |
|---|---|
| `subdomain --verify` / `verify` 子命令 | 对枚举结果做 **DNS 解析 + HTTP 探活**（并发默认 8，低频克制；可解析主机超过 120 个时自动限流），输出 `subdomains_live.txt` / `.json`。实测 xycovo.com：5 个子域 → 4 个可解析，已失效的 `mianjing` 被正确滤除 |
| `api` 取证模式 | 命中且**存活复验通过**的端点，自动落盘 `meta.json` + `response.snippet.txt` + `repro.md`（含可直接复跑的 curl 与"预期现象"），把"疑似"变成"可交稿证据" |

### 6.2 自审发现（对新增代码再当敌人审一遍）

| 编号 | 严重度 | 问题 | 修复 |
|---|---|---|---|
| F5 | 中 | `save_evidence` 用 URL 的 netloc 直接做目录名 → 畸形 URL（如 `http://../../evil/x`）可造成**目录穿越**，把存证写到 `out/` 之外 | host/slug 走白名单清洗 + 去掉首尾点号（纯 `..` 也挡住）；新增穿越回归测试 |
| F6 | 低 | `dns_lookup` 借用了进程级 `socket.setdefaulttimeout` 却不恢复，会污染同进程其它调用 | 保存/恢复原值（含 finally），并加测试断言默认超时不变 |
| F7 | 低 | `run_verify` 读文件未用 `with` 管理句柄 | 改为上下文管理器 |

### 6.3 回归结果

- 第一轮四类陷阱场景复跑：仍然 **0 误报**；真暴露场景仍然全部检出 → 新功能未引入回归。
- 测试总量：**35 项**（含存活验证与取证模式的 7 项新测试 + 目录穿越边界用例），本地与 CI 同步。
- 真实目标实测：`python src/recon.py subdomain -d xycovo.com --verify` → 5 子域 / 4 存活 / 2 个返回 200、2 个被 WAF 拦（467）——**结论按真实响应如实记录**，不做推断。

## 七、第三轮审计（同日，资产档案 + 证据包）

新增 `report` 模块（聚合 report.md + 证据 zip），按同样标准复审：

### 7.1 能力

- `report.md`：归属线索（反查域名 + ICP）/ 子域存活 / 指纹 / 敏感路径 / API 暴露 / 待人工跟进清单；
- 证据包：把 `out/evidence/` 打成 `evidence-<目标>-<时间>.zip`（归档名相对化），随提交稿交付；
- `all` 结束时自动生成；也可 `recon.py report -t <目标>` 按已有产出重建。

### 7.2 自审发现

| 编号 | 严重度 | 问题 | 修复 |
|---|---|---|---|
| F8 | 中 | 渲染层直接采信 `icp_*.json` 的 `filed` 字段 —— 历史版本把接口限频写成了 `filed=true, icp="查询失败"`，档案里就会印出"备案号：查询失败" | 渲染层做有效性校验（值非空且不含"查询失败"才认定），并加脏数据回归测试 |

### 7.3 其他审计关注点的处理

| 关注点 | 处理 |
|---|---|
| 档案是否泄露敏感值 | `report.md` **只写端点/状态码/大小/证据目录**，不内联口令、会话、密钥；敏感内容留在证据文件里，测试断言 report 中不出现证据里的假密钥 |
| zip 归档路径 | 归档名一律相对 `out/`（不含绝对路径、不含 `..`），有测试断言 |
| 中断容错 | 在"什么都没有"的空目录上生成档案不崩（侦察中途失败是常态），有测试 |
| 幂等 | 重复生成覆盖自身，不追加（测试断言两次生成体积一致） |

### 7.4 回归结果

- 测试总量 **41 项**（新增档案/证据包 6 项），本地与 CI 同步；
- 证据包实测：mock 靶站 `/real` 场景产出 5 个暴露端点 → 打包 **15 个文件 / 9.0 KB**（每个端点含 meta.json + response.snippet.txt + repro.md）。

## 八、审计原则（写给未来的自己）

1. **自研工具也要当敌人审**：先问"它会在什么情况下骗我"，再问"它好不好用"。
2. **假阳性比漏报更贵**：漏报只损失机会，假阳性会污染报告、消耗信誉（EDUSRC 驳回的教训）。
3. **"命中"≠"存活"**：任何探测结论都要有复验动作，报告只写复验通过的东西。
4. **审计要有可复现的证据**：可控靶站 + 一键脚本 + 前后对照表，比"我看过了"强一万倍。

## 0. 一句话定位

**不新增第二套样式，只给现有 31 个颜色令牌配第二组值**：深色即现役「石板声呐」原值一字不动（默认），浅色「工程台」为纯增量；主题切换靠 `<html data-theme>` 翻转变量值，组件层 `app.css` 零改动、页面结构零改动。工程美学的识别签名——多级底色阶差、1px 发丝线、单一青鹤强调、圆形声呐 LED、等宽数据列、斑马纹数据行——在两套主题里全部保留，只是明暗方向反转。

## 1. 策略：为什么是「一套变量、两套值」

三条原则：

1. **一套语义变量。** 现状已满足前提：颜色只存在于 `css/tokens.css`，`app.css` 全文零裸色值（本轮实测：`grep -nE '#[0-9a-fA-F]{3,8}\b|rgb\(|hsl\(' css/app.css` 零命中）、`index.html` 零内联 style（`grep -n 'style="' index.html` 零命中）。因此「主题」=「同一批 `--变量名` 的另一组值」，切换主题不需要碰任何选择器——这是本方案成本可控的根本原因。
2. **深色即现役，落地零回归。** `:root` 里深色值与生产 `tokens.css:11-87` 逐字一致；浅色整块追加在 `:root[data-theme="light"]`。不选浅色，应用行为与今天完全相同。
3. **值变、语义不变。** `-lo` 描边档 / `-bg` 淡底档伴生结构、状态色相族（绿=完成、橙=警示、红=故障、灰=待命）、「青鹤是唯一强调色、绝不参与状态语义」（DESIGN.md:184）——两套主题共用同一条纪律。浅色下个别值的**方向**会反转（见 §2.8 与 §3），但变量名和消费它们的 CSS 不感知方向。

为什么默认深色：沿用 DESIGN.md:168-173 的既有论证（实时遥测值守场景、等宽终端语汇、家族基因、长值守用眼成本），本方案不推翻它，只是把「浅色工程台」作为可选档补给 daylight 场景（强光办公室、投屏演示、打印截图偏好浅色的使用者）。

## 2. 主题切换机制

### 2.1 属性契约

- 挂载点：`<html data-theme="dark|light">`。
- **缺省 = 深色**：无属性、属性缺失、值非法，一律回落深色（`:root` 本身就是深色值，天然兜底）。
- 切换动作只有一件事：改 `documentElement.dataset.theme`。

### 2.2 启动无闪烁（theme-boot.js）

CSP 为 `style-src 'self'; script-src 'self'`（`index.html:6`），禁止内联脚本与内联样式，因此启动恢复主题必须走**外部同步小脚本**，在 `<head>` 内、首绘之前执行：

```html
<link rel="stylesheet" href="css/app.css">
<script src="js/theme-boot.js"></script>
```

```js
/* js/theme-boot.js — 首绘前恢复主题偏好；不可用则保持深色默认 */
(function () {
  "use strict";
  try {
    var t = localStorage.getItem("recon.theme");
    if (t === "light" || t === "dark") {
      document.documentElement.dataset.theme = t;
    }
  } catch (e) { /* localStorage 不可用：静默保持深色 */ }
})();
```

选深色的用户（默认）连属性都不用写，零闪烁；选浅色的用户在首帧前就完成翻转。

### 2.3 设置页控件

五页信息架构不变，切换控件落在**设置页顶部**新增一个「界面主题」表单行（设置页现有结构见 `index.html:197-210`、绑定模式见 `settings.js:96-101`）：

- 两枚分段按钮：`深色（默认）` / `浅色`，id `themeDark` / `themeLight`，复用 `.btn` 体系；
- **当前项**用 `.btn-primary`（青底）+ `aria-pressed="true"` 表达，另一枚普通 `.btn` + `aria-pressed="false"`——零新增 CSS；
- 点击即切换：立即生效 + 持久化 + toast 回执（「已切换到浅色主题」，复用 `App.toast`）；
- 不加快捷键、不加顶栏开关：主题是低频设置，不占顶栏与键盘协议（Esc / Ctrl+1..5 契约不动）。

### 2.4 持久化：唯一例外键

现状约定「会话内存（刷新即失，不用 localStorage）」（`js/app.js:180`）——它约束的是**任务数据**（目标输入历史、跨页预填槽）。主题是界面偏好，不是任务数据，每次启动都被重置回深色属于坏体验。故立一条**明示例外**：

- 键名 `recon.theme`，取值仅 `"dark" | "light"`，是全应用唯一 localStorage 键，写入 DESIGN.md Don't 例外条款；
- 备选方案（后端 config 接口存偏好）成本高、引入网络依赖，v1 不做。

### 2.5 切换的动效纪律

现行动效硬约束「颜色、边框、填充类状态一律即时切换、不做补间」（DESIGN.md:175，`app.css:474-476` 悬停即时换色同源）。主题切换本身就是一个超大号的颜色状态变化：**瞬时全量翻转，不加任何 transition**。LED 呼吸（opacity 通道）与 toast 进场（transform 通道）与颜色无关，切换前后继续正常工作；`prefers-reduced-motion` 兜底块（`app.css:699-705`）不受影响。

### 2.6 回退与异常

- localStorage 读取抛异常（禁存储环境）→ try/catch 静默，保持深色；
- localStorage 被清理工具清掉 → 回落深色默认，可接受；
- 写入失败 → 当次会话内主题仍生效（属性已挂），下次启动回落深色。

### 2.7 不跟随系统

不做 `prefers-color-scheme` 自动跟随：产品定调是深色控制室（DESIGN.md:168-173），跟随系统会让「默认体验」随 OS 设置漂移，与产品论点冲突。如后续有需求，加「跟随系统」第三档另行提案。

### 2.8 方向反转的语义说明（读 tokens.css 前必看）

浅色下两个伴生档的**方向**与深色相反，这是语义令牌的已知取舍：

- `--acc-hi`：深色=更亮青（悬停变亮）；浅色=更强对比的深青（悬停**加深**，浅色 UI 悬停惯例）。主按钮悬停、链接、运行态字全部消费它，CSS 无需改动。
- 阴影：深色用黑底阴影压层次；浅色阴影减淡（`rgba(16,31,43,.10/.16)`），层次主要靠边框与底色阶差——与深色「纵深靠阶差不靠阴影堆叠」（DESIGN.md:207）同一条哲学。

## 12. 风险与不适用场景

1. **WebView2 系统「高对比度」forced-colors 模式**：系统会整体覆盖页面配色，本方案未适配，v1 不承诺；如需要另立提案（`forced-colors` 媒体查询）。
2. **新增颜色忘配浅色值**：`var()` 会静默回落 `:root` 深色值，白底上可能不可读——靠门禁 1/3/4 与 DESIGN.md Don't 条款兜底，评审时对照表即 diff 基线。
3. **`--acc-hi` 名实方向相反**（浅色下是「更深」不是「更亮」）：语义令牌的已知取舍，组件 CSS 不感知；已在 tokens.css 注释与 DESIGN.md 更新中显式说明，防新人误读。
4. **浅色描边档整体偏实**（`--acc-lo` 3.62:1 vs 深色发丝带 1.68:1）：有意取向——白底上发丝描边必须更实才可见；走查时确认观感统一即可，不算漂移。
5. **点阵底纹低分屏莫尔纹**：DESIGN.md:267 既有 r2 待办，浅色 8% 值一并纳入实机复核。
6. **证据截图跨主题观感差异**：数据一致，仅观感不同；对外提交证据材料建议固定深色（默认档）截取。
7. **不适用场景**：打印场景（桌面端无打印需求，未定义 print 样式）；需要品牌个性化的场合（本方案刻意只提供两档，不做主题自定义）。

## 13. 明确不做

- 不做强调色/主题色自定义、不做第三主题。
- 不做 `prefers-color-scheme` 跟随系统（§2.7）。
- 不做 forced-colors 高对比度适配（§12.1）。
- 不做日志语法高亮着色（日志必须字符原样）。
- 不引第三方主题库 / 图标库 / 样式库（零外链纪律不变）。
- 零 AI 功能、零对话组件、零联网模型调用、零遥测——主题机制同样纯本地，无任何网络行为（铁律）。
- 提案阶段禁止动生产 `frontend/`（本方案全部改动停留在 docs/design-proposals/）。
